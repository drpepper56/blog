Telegram Mini App Parcel Shipment Tracking

Typescript + Rust + MongoDB + 17Track API

A simple mobile app made using the Telegram mini app environment [put link here] to get detailed tracking information and push notifications about order updates through telegram. The motivation behind this project was a nomination at hackathon I went to last year, a team of one won with a project that integrated a Solana wallet into telegram using a mini app.

The app is written in typescript with basic CSS, it works as a single page application, elements are swapped in and out of view to show different sides of the app. Telegram Bots make it possible to run website-like applications natively on telegram, the bot is used to manage notifications, client server URLs and much more.

Authentication is done using the telegram account, so the user never sees a register or login page, the account is liked to the user’s telegram user ID, which is stored on the server in its raw form and as a hash digest for telegram notification and authentication purposes.

There are currently 3 ways to open the app, the OPEN button in the telegram chat window on the bot, a direct link from the QR code. These two open the app normally, which is when it loads the user’s tracked packages list. The third way is through an update notification, then the program loads only the data of the package from the notification and upon going back to the main screen it pulls all the data from the server.

Registering a tracking number can be done currently up to 4 times for free due to the API cost. If the API was not able to detect the carrier, the user will need to specify it, they can search for the carrier from a long carrier list supported by the API so it’s really easy to add it.

Users have an option to give a name tag to a tracking number like “new TV” or “running shoes”. To avoid database overhead, telegram cloud storage was used to store them, it only allows up to 1024 key-value pairs so it’s not scalable, but it’s enough for a proof of concept. The name tags are retrieved the same way as the tracking data, get only the relevant name tag if opening a notification, then get the rest when going to the tracking list.

The main page of the app is a list of tracking numbers that display the username tag, tracking number and latest event description. Clicking one of those windows shows all shipping events. At the bottom of the page, the buttons give the user options to subscribe or unsubscribe to tracking updates and remove the tracking number from their list, which cannot be undone.

Name tags can be changed when clicking on them on the details page, if no name tag is set, a default blue text will let the user know they can set it.

A walkthrough and rationale of steps taken in completing the capstone project for Google Data Analytics Certification on Coursera. Data was cleaned and transformed using R dplyr, visualizations were made using Tableau. Full transformation script, data source and a more numerical documentation is available at the end of this article.

The subject of the dataset is a urban bike renting company from Chicago, the data only includes records of trips and the attributes do not hold any user information. Loading the huge data set from separate csv files to one data frame in R was done using a recursive function that took a list of files and returned the data frame.

Cleaning and Transformation

Missing values were found in columns that describe the start and end station name and ID number, station longitude and latitude.

The coordinate values had various number of significant figures after the decimal point, considering this, to make it easier to work on the each individual, they were split into latitude and longitude fields. Records with missing names or IDs of stations were given the values of records with only very close coordinate matches. The same was done in reverse, giving coordinate values to fields with matching name and ID of a station. Coordinate values slightly varied in groups of matching station name and ID so the coordinate values were served based on the mode from the group.

Data Inconsistencies were found in the names and ID values of stations. Mismatched name and value pairs

All names were trimmed of spaces, prefixed and suffixes in names like “Temp” or “Public Rack” where removed if the same ID was found without the extra text. In some cases the names prefixed with “Public Rack” had the same IDs but a different group of coordinate values, making their difference valid, the IDs from that group were prefixed with PR to preserve that data. After that there were 8 inconsistencies left, some had unique suffixes that were removed, random numbers were replaced with matching ID names and the “true” inconsistencies left were fixed by adding a D prefix to the ID value of the group with less entries.

ID inconsistencies were easily fixed after the previous step by assigning the majority ID value to the whole group.

The combined field was split into separate time and date field to make it easier to work on. Records that had missing time or date or start time recorded chronological after the end date, were removed. A field for trip duration was added

Where the coordinates were accurate enough a distance field was added, otherwise it was set to NA. Records with distance zero and both start and end station set and different to each other were removed.

Added a field to hold the average speed of the trip by dividing the trip distance by the trip time.

Outlier Removal

Outlier values only happened in numerical fields for distance, time and speed.

Trips with duration over 90’000 seconds and under 7 seconds were removed.

A few trips with over 50 kilometers were in a group with around 9’800 kilometers values, they were removed.

Speed was analyzed separately for electrical and regular bikes, but no lowest speed limit was set, electric bike trip speed was capped at 9 meter per second and 8.5 meters per second for regular bikes.

Most of these limit values were found by looking at the shape of distribution graphs and identifying the point after which the number of trips didn’t follow the distribution curve or dropped significantly.
